## 0.1.13 删除 / 作废 / 恢复三分 + 分类字典可维护

用户三条要求（原话）：
1. 管理员可以删除报价单(包含已经发出的报价单)、物料库、物料价、人员库、供应商；
2. 成员不能删除上述，但可以作废和恢复；
3. 设置-分类字典，管理员可以新增修改物料树名称和人员树名称。

### 定的规矩
- **分界线是可逆性，不是重要性**：作废可反悔 → 两种角色都能点（`canArchive`）；删除不可逆 → 只有管理员（`canDeleteRecord`）。改价仍只给管理员。
- **物料连带删价、供应商拒绝删**：删物料只带走它自己那几家的价；删供应商会一次性带走十几个物料的价，比价表里"最便宜的那家"会静默换人。爆炸半径不同，处理方式不能一样。
- **草稿也能作废**：成员不能删之后，建错的草稿原先是死胡同（不能删、不能作废）。恢复按 `issued_at` 回到 issued / draft。
- **`DELETE /items/:id` 从"停用"改回真删除**。0.1.12 及以前名字叫删除、行为是停用，管理员以为删干净了。

### 改到的地方
- `domain/permissions.ts`：+`canArchive` / `canDeleteRecord`，能力表 +3 行
- `server/http.ts`：+`requireArchive` / `requireDelete`（403 文案固定为「你可以用『作废』——作废之后随时能恢复」）
- `domain/quote-status.ts`：`canVoid` 放开到 draft，+`canRestore`
- 新路由：items/archive|restore、prices/restore、suppliers/archive|restore、quotes/restore；prices/[id] + DELETE
- `items-write.service`：`setItemActive` / `itemDeleteImpact` / `deleteItem`（先删 price_change_logs，否则 RESTRICT 删不掉价）
- `price-patch.service`：`restorePrice`（先查同口径在效价，撞了 40902 说清是哪家哪段）、`deletePrice`
- UI：四个列表加「含已作废」开关 + 已作废徽章；报价单操作列 作废/恢复/删除；比价页下方新增「价格记录」表（此前 `archivePrice` 接口存在但**没有任何界面入口**）；分类字典从只读改为改名 + 新增
- `globals.css`：`.btn--link.t-danger` / `.btn--icon.t-danger` 复合选择器 —— `.t-danger` 与 `.btn--link` 同权重且定义在前，之前"删除"和"作废"长得一模一样

### 踩到的坑（下次直接看这条）
- 服务层返回体必须 **snake_case**：`setItemActive` 一开始写成 `isActive`，前端边界转出来还是 `isActive`（碰巧能跑），但自检脚本读 `is_active` 读到 undefined，判成"作废失败"。接口约定不是风格问题。
- python 文本模式写 `package.json` 会引入 `\r\n`，`deploy/pack.sh` 的 CR 门禁直接拦。改 json 一律二进制模式写。
- `node scripts/db.mjs start` 是**前台阻塞**的，必须 run_in_background；前台跑会被 SIGTERM 掉，看起来像"启动失败"。
- Git Bash 会把 `/quotes` 这类参数转成 Windows 路径，脚本里别直接把 CLI 参数当 URL 用。

### 证据
- `tsc` 干净，单测 **57/57**（新增 `tests/permissions.spec.ts` 7 条，专钉这条边界）
- `deploy/verify.mjs` 自检 **46/46**（37 → 46，新增 9 项：三个"成员删被拒"、物料作废恢复闭环、价格作废恢复、分类新增/改名/成员被拒）
- 生产构建 1440×900 实测截图：报价单操作列「继续编/作废/删除」、删除为红色；物料库成员视角只有 3 个图标（无垃圾桶）；勾「含已作废」后首行带徽章 + 恢复图标；分类字典铅笔按钮 + 新增面板
- 数据清理：报价单 0 张、已作废主体 0、已作废价 0、临时分类 0

## 第十一轮 · 0.1.14 · 登录页密码改成框内眼睛图标

**诉求（客户原话）**：登陆页面-密码，露出来和藏起来修改成一个眼睛图标放在密码框右侧，功能不变。

### 改了什么

- `components/ui/field.tsx`：新增 `PasswordInput`（受控：`visible` + `onToggleVisible`），眼睛按钮 `type="button"` 落在 `.input-affix` 容器内右侧；`aria-label` 随状态在 显示密码/隐藏密码 之间切
- 同时删掉 `Field` 的 `aside` 插槽 —— 唯一调用点就是这个被替换掉的文字按钮，留着会让下一个人再把开关放到离它管的那一格 20px 远的地方
- `app/login/page.tsx`：`<Input type=password>` → `<PasswordInput>`，去掉 `aside` 文字按钮
- `app/globals.css`：`.input-affix` / `.input-affix__toggle`（28×28、right 4px、`padding-right: 40px` 让文字不钻到图标下面）
- `app/globals.css`：`.login__form` 宽 `360px` → `min(360px, 100%)`

### 两个判断

- **图标说"点了会发生什么"，不说"现在是什么状态"**：藏着给睁眼、露着给闭眼。与明细表 `IconEyeOn/IconEyeOff` 那条约定一致（`quote-line-row` 里 `isVisibleToCustomer ? EyeOff : EyeOn`）。
- **焦点环要画在图标内侧（inset）**：第一版用 `--shadow-focus` 外扩 4px，图标离右边框只有 4px，环直接压在输入框边框上，截图里像两个框叠在一起。改 `inset 0 0 0 2px var(--accent)` 后干净。
- **顺手修的真 bug**：375px 屏上 `.login__right` 两侧各 32px → 只剩 311px，360px 定宽的表单连同「登 录」按钮一起溢出视口，新眼睛正好长在被切掉的那一侧 = 手机上这个功能不存在。`min(360px, 100%)` 修掉。

### 验证（生产构建 / 无头 Chrome CDP）

- `tsc` 干净，单测 57/57
- 1440×900：默认睁眼；点一下 `type=password → text`，值不变；再点回去；图标矩形完全落在输入框内（`inside: true`，gapRight 4px，居中对齐 0px）
- 键盘：Tab 从 `#password` 落到按钮（`activeElement.className = input-affix__toggle`），Enter → `type=text` 且 `location.pathname` 仍是 `/login`（没提交表单），空格 → 回到 `password`
- 放大 3× 截了 idle / hover / focus 三态；375×812 下图标完整在视口内、表单与按钮左右对齐
- 顺带确认 `Field` 去掉 aside 外层 `flex justify-between` 后，`新建成员` 抽屉里 4 个标签仍全部左对齐（x 一致、宽 447）

### 教训（补第 10 条）

- 换 CSS 变量做焦点环前先看元素离边框多远。`--shadow-focus` 是"外扩 4px"语义，任何贴边元素都不适用。
- CDP `Input.dispatchKeyEvent` 要用 `type:'keyDown'` 才会触发按钮默认行为；`rawKeyDown` 下 Enter 不激活按钮，会误判成"键盘不能用"。
