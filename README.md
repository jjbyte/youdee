# 有底 — 活动物料 / 人员供应商价格库 + 报价单

给活动策划公司用的内部工具。解决的问题只有一句话：**同一个物料、同一个岗位，不同供应商报的价不一样，而这些价现在散在微信聊天记录和几个人的记忆里。**

系统做两件事：

1. 把每个物料、每个岗位的价格按「供应商 × 交易性质 × 含税口径 × 计价单位 × 生效期间」记下来，改价留痕、旧价不丢；
2. 报价时按项目类型把毛利算清楚，并按「谁更便宜、便宜多少、为什么不能用这家」摆出来。

明确**不做**的：项目成本核算、ERP、财务对接、对外报价门户。这是价格底账，不是业务系统。

## 一、五分钟跑起来

前置：Node.js ≥ 20.19（本项目实测 22.22.2）。**不需要 Docker** —— 本地数据库用的是真 PostgreSQL 18.6 二进制（`embedded-postgres`）。

```bash
# 1. 装依赖（版本已在 package.json 里逐个锁死，不要用 ^ 或 latest）
npm install

# 2. 起数据库（前台阻塞，另开一个终端；默认 127.0.0.1:55432）
npm run db:start

# 3. 建表 + 灌种子数据（第一次）
npm run db:migrate
npm run db:seed

# 4. 起开发服务器
npm run dev            # http://localhost:3000
```

## 二、几条不是"功能"而是"不出错"的设计

这些点看起来像细节，但每一条背后都是一次会报错价的场景。

**改价 = 新增一条 + 关闭旧价，永远不覆盖。**
价格记录有生效期间，数据库层用 `EXCLUDE USING gist` 六维约束保证「同一主体 + 同一供应商 + 同一交易性质 + 同一含税口径 + 同一计价口径 + 重叠期间」不可能同时存在两条。想改就直接改，会拿到一句人话提示，而不是数据库错误码。

**含税价与不含税价不混排。**
一张单声明一个口径（默认含税）。不同口径的供应商**照样显示在页面上**，但标灰、写明"该供应商只报了不含税价，与本单口径不同，不参与排序"——而不是悄悄算进最低价里。这两者混算，结论会反。

**按场和按天不混排。**
讲师「按场 2800」和「按天 1500」都属"人员服务"，但一场含几天不在价格里，本来不可比。系统按计价口径分组，各组各算各的最低价。LED 屏的买断价和租赁价同理。

**跨单位比价靠折算系数，不靠猜。**
喷绘按㎡报价、淘宝按张卖，两者要能比，必须有人填「1㎡ = 几张」。填了才参与排序，没填就标"不可比"并说明原因。系统**不会**替你假设 1:1 —— 那会把"我不知道"静默变成"我断言相等"。

**毛利低于预警线只是提醒，不拦出单。**
预警线按项目类型分（年会 18% / 发布会 22% / 展台 25% / 路演 15% / 框架客户 12%）。有些单是故意亏的（走量、拿案例、维护关系），系统只把话说清楚，按不按发由人决定。**唯一能拦住出单的是三件事：客户名空、活动名空、有行没有成本。**

**报价单是全量快照。**
发出去的单里存的是当时的名称、规格、单位、成本、对客价、供应商名，不是价格的引用。三个月后供应商涨价、主体改名、价格被归档，历史单上的数字一个字都不会变。

## 五、还缺客户提供的东西

**单位折算表**。下面这些物料的真实折算关系只有客户知道，系统不能凭空填：

| 物料 | 比价基准 | 供应商常按 | 需要确认 |
|---|---|---|---|
| 喷绘布 | ㎡ | 张 | 1㎡ = 几张 |
| KT 板 | ㎡ | 张 | 1 张 = 几㎡（常规 1.2×2.4m） |
| 桁架 | m | 根 | 1 根 = 几米 |
| LED 屏 | ㎡ 或 天 | 块 / 套 | 1 块 = 几㎡ |
| 地毯 | ㎡ | 卷 | 1 卷 = 几㎡ |
| 易拉宝 | 个 | 套 | 是否含画面 |

不填不会崩：这些物料仍然能录价、能出单、能看到各家原价，只是**不标"最低"**，比价页会写明"未填折算系数，不可比"。填了才会出现"某某家便宜 6.25%"这类结论。

## 六、部署到 Linux 服务器

打包：

```bash
deploy/pack.sh          # 产出 dist/youdee-<版本>-<日期>.tar.gz 与 .sha256
```

包里只有源码和部署脚本（**不含** `node_modules` / `.next` / `.env` / 上传的附件）。
`node_modules` 必须到目标机上重装：`sharp`、`pg` 是平台相关二进制，Windows 上装的那份
拿到 Linux 上会在上传图片或连数据库时才崩。

部署两条路径，详细步骤与故障对照见 **`docs/05-DEPLOY.md`**：

| 路径 | 命令 | 适用 |
|---|---|---|
| A. Docker Compose | `deploy/deploy.sh root@服务器IP` | 推荐，失败面最小 |
| B. 裸机 Node + PG | `sh deploy/manual-deploy.sh` | 不便装 Docker 时 |

部署完成后**必须**跑一次自检：

```bash
node deploy/verify.mjs
```

它走完整条链路（登录、比价、同一价两个接口是否同一个数、出单、导出、成员改价被拒、
区间重叠被拦、错误响应不含数据库术语），每项都比对具体数值。
只看到"网页能打开"不能算部署成功 —— 这个系统最危险的缺陷全都不报错，只是数字不对。
